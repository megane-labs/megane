# Changelog

## [Unreleased]

### Added

- **Camera alignment with the crystal and Cartesian axes, and a VESTA-style default view (#661).** The viewer's top-left corner gains two rows of axis buttons under Reset View: ±a / ±b / ±c (shown while the structure carries a cell) and ±x / ±y / ±z. Each turns the camera to look straight along that axis from the named side — "+a" puts the +a end of the cell toward the viewer, like VESTA's a* toolbar button — keeping the current target, distance and zoom, with c held upright for the a/b views and b for the c views. The initial view and "Reset view" now use VESTA's "Standard orientation of crystal shape", computed from the actual lattice vectors rather than a fixed rotation matrix so monoclinic and triclinic cells are honoured: +c up the screen, +b to the right, then the eye swung by arctan(1/3) ≈ 18.435° around the vertical axis and raised by arctan(1/6) ≈ 9.462° above the ab plane, so the +a end of the cell comes toward the viewer at the lower left and the top face shows. Structures without a cell use the Cartesian frame (a = x, b = y, c = z) for both. The fit now measures the structure's extent along the screen axes of whichever orientation it frames, and for structures without a cell it bounds the atoms' van der Waals spheres rather than their centres — a small molecule seen along its long axis projects to a very short span of centres, and the old fit put its spheres off screen — so a re-fit frames the whole molecule from any direction. The buttons ship on every host (webapp, JupyterLab labextension, VSCode editor, and the Jupyter widget in JupyterLab / VSCode notebooks); `MeganeViewer` exposes them through the new `ui.viewAxes` switch, the renderer through `MoleculeRenderer.alignCameraToAxis("+a" | … | "-z")`, and the npm library exports the underlying `standardOrientation` / `axisOrientation` helpers. Every E2E pixel baseline moved with the new default view.

- **Color-by-volume mapping for the Isosurface node — ESP-mapped charge densities.** The node gains a second volumetric input, `colorVolumetric`, and a `colorMode` parameter: with `colorMode: "volume"` the surface's vertex colors are produced by trilinearly sampling the connected color volume (e.g. an electrostatic-potential cube) at each vertex of the isosurface (e.g. an electron-density contour) and mapping the values through a `colormap` — `"rwb"` (red→white→blue, the chemistry ESP convention, the default), `"bwr"`, or `"rainbow"` — with an optional explicit `colorRange` (`[min, max]`; omitted = auto, symmetric around 0 for the diverging maps). Sampling handles non-orthogonal CUBE step lattices and clamps outside the grid; without a connected color volume the node warns and falls back to its solid colors. Wired through every surface: node UI (color-by selector, colormap picker, min/max range inputs), execution engine, serialization, AI prompt/node reference catalog, and the Python API (`Isosurface(color_mode=..., colormap=..., color_range=...)` with the new `inp.color_volumetric` port).

- **`illustrative` representation and color mode — Mol*'s illustrative style (Goodsell-like figures).** The Representation node gains `"illustrative"`: spacefill spheres at the full van der Waals radius, flat unlit shading, and a constant-width dark silhouette outline, with bonds hidden (the touching spheres already swallow them). The Color node gains a matching `"illustrative"` mode, ported from Mol* 5.11.0's own source: every atom takes its entity color and carbon is only a lightened shade of that same color (CIE Lab L* + `18 * carbonLightness`, Mol*'s `Color.lighten`), so each chain reads as one flat body. Chains are indexed by serial in order of first appearance, as Mol* does, and water gets its own color; megane's chain ID stands in for `label_entity_id`. The palette itself is a deliberate deviation: rather than Mol*'s fully saturated `many-distinct` list, megane softens its own `CHAIN_COLORS` into pastels in CIE LCh (hue preserved, lightness raised, chroma halved), and puts the water color through the same transform. The Lab lightening math is asserted bit-for-bit against output generated by Mol* itself. Pair the two for the full Mol* preset (`Color(mode="illustrative") → Representation(mode="illustrative")`); either works on its own. Available in the visual editor, the Inspector's appearance panel, the pipeline JSON, and the Python/TypeScript builders. Unlike Mol*, which composites its outline and ambient occlusion as screen-space post-processes over the depth buffer, both effects are approximated inside the impostor's own fragment shader: the outline as a constant-width band at the sphere's silhouette, and the occlusion as a radial ramp toward that silhouette — in a spacefill field the dominant occlusion term is contact with neighbouring spheres, which always sits near a sphere's rim. That needs no extra render target and behaves identically in the offscreen render/capture path and on every host, at the cost of not darkening large pockets the way a true SSAO pass would.

- The TypeScript pipeline builder's `RepresentationMode` was missing `"licorice"`, which the Python builder, the JSON schema and the renderer have all accepted for some time; it is now in the union alongside the new `"illustrative"`.

### Fixed

- **Codecov stopped gating Dependabot PRs, and the "fail CI when the upload fails" switch turned out never to have been wired up.** Two independent bugs with one visible symptom: `codecov/patch` never appeared at all on Dependabot PRs (#671, #680–#682), which left them sitting unmergeable behind a required check that never ran. (1) GitHub does not pass repository Actions secrets to Dependabot-triggered runs, so `secrets.CODECOV_TOKEN` resolved to an empty string and Codecov rejected the tokenless upload with `{"message":"Token required because branch is protected"}`; the token therefore has to be stored a second time as a **Dependabot** secret (Settings → Secrets and variables → Dependabot). Fork PRs are unaffected — Codecov does accept tokenless uploads from forks — and the timeline points at the repository move: Dependabot PRs before it (e.g. #651) did get a `codecov/patch` status, none after it did. (2) All three upload steps passed `fail_ci_on_error: true`, but codecov-action's input is spelled `fail_ci_if_error`; an unknown input is silently ignored, so `CC_FAIL_ON_ERROR` stayed at its `false` default and the rejected upload was reported as a successful step. That is why the missing gate stayed invisible — the "hard merge gate" of CRITICAL RULE #8 had never once failed a job on an upload error. The `test-rust`, `test-ts` and `test-python` jobs now share a `.github/actions/codecov-upload` composite action which spells the input correctly and, before uploading, fails the job with an explicit message when a run that is not a fork PR has no token — instead of going green with no coverage reported.

- **A Color node no longer silently cancels the Modify node's per-atom scale and opacity.** Painting colors resets the atom mesh to base CPK by reloading the snapshot before the new overrides are applied, and that reload also zeroes the per-atom scale, opacity and hidden buffers — which belong to other layers entirely (the Modify node, and the per-atom representation split that draws e.g. water as lines). Since `applyViewportState` applies those overrides *before* the color pass, any pipeline carrying a Color node discarded them. Most visibly this made the `illustrative` preset's spacefill spheres impossible to shrink, because that preset always pairs a Color node with the Representation node: a downstream `Modify(scale=0.5)` computed the right buffer, handed it to the renderer, and had it wiped microseconds later. The renderer now pushes the per-atom scale, opacity and hidden mask back after the reload (scale first, so the hidden mask still composites on top of it). Wiring a Modify node into a plain ball-and-stick pipeline always worked, which is why the bug survived: it only appears once a Color node joins the chain.

- **The viewer no longer nondeterministically shows the structure file's coordinates instead of the current trajectory frame.** While a trajectory streams in, the boot-time pipeline executes several times and the snapshot and frame geometry updates could land in either order; when the snapshot landed last, the displayed geometry at "frame 1/N" was the structure file's positions (e.g. a minimized PDB) rather than trajectory frame 0 (its XTC) — a coin flip per load. The Viewport now re-applies the current frame after every snapshot load, so frame data always wins while a trajectory is loaded. The E2E `pinFrame` helper gained the matching determinism guard, and the affected webapp baselines (which had encoded the structure-coordinate variant) were re-recorded.

- **Transparent ball-and-stick now renders as one fused solid instead of beads threaded onto rods.** Bond cylinders run from atom centre to atom centre, so both ends sit buried inside the endpoint spheres. An opaque atom hid that via the depth test, but fading atoms (a `modify` node's opacity, or the atom-opacity control) stops the sphere writing depth, and the buried stick blended straight through the ball. The bond fragment shader now renders the CSG union of stick and balls: fragments falling inside either endpoint sphere are discarded, so each stick ends exactly on the ball's skin at any viewing angle. Opaque renders are pixel-identical — the discarded fragments are precisely the ones the depth test was already rejecting — and a measured A/B showed no frame-cost change (359.2 → 358.2 ms CPU/frame, inside run-to-run noise), because the trim removes as much shading work as its two sphere tests add. The trim switches itself off for an endpoint whose ball draws nothing (hidden by a representation, or faded out entirely), so a stick with no ball stays whole.

### Changed

- **Camera rotation is now a free trackball: it no longer stops at the poles (#662).** Left-drag used three.js `OrbitControls`, which keeps `camera.up` pinned to the world c axis and clamps the polar angle, so a vertical drag stalled once the view reached the ±c pole and could never continue over it. The viewer now rotates with `TrackballControls` (wrapped in `src/renderer/CameraControls.ts`): the model turns continuously in any direction, including across the poles, and the camera's roll follows the drag. Two details of the stock trackball were adjusted along the way — pointer motion between two render frames is accumulated instead of being overwritten (stock `TrackballControls` drops all but the last pointermove segment, which made drags sluggish with high-rate mice or slow scenes), and motion is static (1:1 with the pointer, no inertial glide whose length would depend on the frame rate). Because the roll is free, `Reset view` and every re-fit restore the canonical c-up orientation, the persisted camera state (localStorage, the widget's `camera_state` traitlet) now carries the `up` vector so a reload restores the exact orientation (older saved states without it still load), and the mouse wheel zooms perspective views with the same reversible ramp orthographic views already used. Middle-drag zoom, touch pinch zoom, and right-drag pan are unchanged.

- **The project moved from `hodakamori/megane` to `megane-labs/megane`, and the docs site moved with it.** The GitHub Pages site is now served at <https://megane-labs.github.io/megane/>; the old <https://hodakamori.github.io/megane/> URL returns 404. Every repository and docs link in the README, docs site, package manifests (npm, PyPI, Cargo, JupyterLab, VS Code) and the in-app tour was repointed. Two of these were functional rather than cosmetic: `package.json`'s `repository.url` gates `npm publish --provenance`, and the LLM proxy's `ALLOWED_ORIGIN` gates CORS for the docs demo's AI chat. The VS Code Marketplace publisher (`hodakamori.vscode-megane`) and all authorship fields are unchanged — they identify a person and a Marketplace account, not the repository.

## [0.14.0] - 2026-08-23

### Changed

- **Every host now opens a file with the same default bonds (issue #668).** The per-format AddBond default ("structure" for formats that embed bonds — PDB, MOL/SDF, LAMMPS data, CML, Chem3D, Odyssey — "distance" otherwise) now lives once in the Rust core (`megane_core::bonds::default_bond_source`, exposed via PyO3 and WASM). `megane.view()` / `view_traj()` / `build_pipeline()` default their `bonds` parameter to the new `"auto"`, which resolves through that shared table instead of always using distance inference — a PDB opened in the Jupyter widget now shows its file-declared bonds exactly like the webapp. Pass `bonds="distance"` for the previous behavior. The TS load path keeps a pinned mirror of the table for its synchronous pre-WASM phase.

- **The Python `.top` / `.psf` topology parsers now delegate to the Rust core (issue #668).** `megane.parsers.top.parse_top_bonds` and `megane.parsers.psf.parse_psf_bonds` are thin wrappers over `megane_core::top` / `megane_core::psf` (via new PyO3 bindings `parse_top_bonds_from_path` and the existing `parse_psf_bonds`), removing the duplicated section/include-resolution logic — Python thereby also picks up the Rust parsers' `[ settles ]`/`[ constraints ]` support. The remaining deliberate JS ports (`inferBondsJS.ts` of `bonds.rs`, `symmetry.ts` of `crystal.rs`) now carry explicit keep-in-sync notes in both files.

- **The CIF parser no longer applies space-group symmetry at parse time — it returns the asymmetric unit plus the raw `symmetry_ops` (parser-purity rule #11; P1 audit item resolved).** Expansion moved into the new `symmetry` pipeline node, which the default pipelines and templates carry in `expand` mode, so what renders by default is unchanged. Caveat: pipelines saved before this change have no `symmetry` node, so a CIF loaded through them now shows the asymmetric unit — add a `symmetry` node after `LoadStructure` (or reload with a default pipeline) to recover the packed cell. Python code calling `megane.load_cif(...)` now sees the asymmetric-unit atom count.

- **Parser purity sweep: every parser now returns exactly what the file asserts (CRITICAL RULE #11; all P1–P3 audit items resolved).** User-visible behavior changes:
  - **Odyssey (`.odydata`/`.xodydata`)**: atom coordinates are kept verbatim (previously shifted by +box/2); the periodic cell is anchored via `box_origin`, so the rendered scene is unchanged but coordinate readouts now match the file.
  - **LAMMPS dump**: `ix/iy/iz` image flags are decoded into absolute coordinates using each frame's own cell (triclinic-correct, matching OVITO/VMD molecule reconstruction), and unwrapped `xu/yu/zu` columns win over wrapped `x/y/z` when a dump carries both.
  - **mmCIF**: every `pdbx_PDB_model_num` model is kept as a trajectory frame (NMR ensembles play instead of losing all but one model).
  - **GRO**: multi-frame files (concatenated `trjconv` output) load every frame — per-frame velocities and varying cells included — instead of silently reading only the first; velocities are converted nm/ps → Å/ps so vector arrows share the geometry's unit system.
  - **Embedded vector channels** (GRO velocities, LAMMPS dump vx/vy/vz) are now *offered* in the Load Vector node via a channel selector instead of being auto-rendered as a load side effect and overwriting the node's file name.
  - **Opening a multi-frame structure file** flips the LoadTrajectory node's new visible `source` parameter to `"structure"` (the node forwards the structure file's own frames) instead of silently deleting the node and rewiring the graph.
  - Cell data in the pipeline carries geometry only — the loader-hardcoded `visible`/`axesVisible` flags on `CellData` are gone; cell and axes visibility remain a Viewport/appearance decision.

- **The AI chat's free-demo backend now supports both Preferred Networks' PLaMo API and OpenRouter, with PLaMo as the default and OpenRouter as a cross-provider fallback.** Both upstreams are OpenAI-compatible (bearer auth, SSE streaming, `tools` function calling), so the frontend's OpenAI-compatible client path and the skill tool round trip work against either unchanged. The Cloudflare Worker proxy (`workers/llm-proxy/`) walks a configurable provider order (`LLM_PROVIDERS`, default `plamo,openrouter`; a provider whose API key secret is unset is skipped): PLaMo has no server-side routing so the Worker retries `PLAMO_MODEL` → `PLAMO_FALLBACK_MODELS` (default `plamo-3.0-prime` → `plamo-2.2-prime`) one request per model, while OpenRouter keeps its server-side `models` routing array (`OPENROUTER_MODEL` + `OPENROUTER_FALLBACK_MODELS`) and its `HTTP-Referer`/`X-Title` attribution headers; the first response that streams wins. `bench/llm/` gains a `plamo` provider alongside the existing `openrouter` one, and the `llm-eval` workflow picks its provider via the `MEGANE_LLM_BENCH_PROVIDER` repository variable (default `plamo`). **Deploying requires both the `PLAMO_API_KEY` and `OPENROUTER_API_KEY` GitHub repository secrets (the deploy workflow uploads both as Worker secrets; the Worker itself tolerates either being empty).**

### Added

- **New `symmetry` pipeline node — visible, toggleable space-group expansion for crystals.** The node has a single `mode` parameter: `"expand"` (the default) applies the space-group operations the parser captured on the structure (a CIF `_symmetry_equiv_pos_as_xyz` loop) to fill one unit cell with the symmetry-equivalent images — a faithful TypeScript port of `crystal.rs::expand_symmetry`, including centroid wrapping into the home cell, special-position deduplication, and per-image bond replication — while `"none"` shows the raw asymmetric unit. Structures without symmetry operations or without a unit cell pass through unchanged, so the node is a transparent no-op for every non-CIF format. It ships on every surface: editor palette (Modify group), execution engine, AI prompt/node reference catalog, the JS `Pipeline` builder (`Symmetry`), and the Python API (`megane.Symmetry`), and is wired in `expand` mode into the default pipelines (webapp seed, VSCode extension seed, external-file seed) and the Molecule / Molecular Crystal / Solid / Surface Mesh / Protein templates, directly after `LoadStructure`, so a loaded CIF still renders its packed unit cell by default.

- **`ParsedStructure` gains per-atom scalar channels and parse warnings, plumbed through WASM, PyO3, and the TS load path.** File information megane does not render yet is now parsed instead of silently discarded: LAMMPS data per-atom `charge`/`mol_id`; VASP Selective-dynamics flags (as a `selective_dynamics` bitmask channel); MOL/SDF V2000 charge and isotope columns (with `M CHG`/`M ISO` overrides and V3000 `CHG=`/`MASS=`); LAMMPS dump extra numeric columns (q, mol, computes/fixes) as frame-synced channels; extended-XYZ `Properties=` columns as vector (velocities/forces) and scalar channels. Parse warnings surface everything a parser must skip — dropped atoms/bond endpoints (Odyssey/Chem3D/CML), unrecognized units, ghost atoms, and multi-record files (extra MOL2 `@<TRIPOS>MOLECULE` sections, `$$$$`-separated SDF records, sibling CML `<molecule>` documents, extra Odyssey structures, JCAMP-DX compound blocks) — in the browser console, `PyStructure.warnings`, and `PySpectrum.warnings`.

- **The Jupyter widget's binary snapshot protocol carries crystallographic symmetry operations** (`HAS_SYMMETRY_OPS`), and `megane.view()` includes a `Symmetry` node, so a CIF shows the same expanded unit cell in the widget as on every other host.

- **New `wrap` pipeline node — a wrap ↔ unwrap toggle for periodic structures.** The node has a single `mode` parameter: `"wrap"` folds every atom back into the home unit cell (box-origin aware, triclinic cells included), `"unwrap"` shifts atoms by whole lattice vectors so bonded molecules split across a periodic face become contiguous again (VESTA/Mercury-style whole molecules; connectivity comes from the file's own bonds, falling back to the same PBC-aware VDW inference the Add Bond node uses), and `"none"` (the default) passes coordinates through untouched. A connected trajectory is remapped per frame — variable-cell trajectories use each frame's own cell. The node ships on every surface: editor palette (Modify group), execution engine, AI prompt/node reference catalog, the JS `Pipeline` builder (`Wrap`), and the Python API (`megane.Wrap`). It is also wired into the default pipelines (webapp seed, VSCode extension seed, external-file seed) and the Molecule / Solid / Surface Mesh / Protein templates in pass-through mode, so toggling wrap/unwrap is one dropdown click away without editing the graph.

- **`MeganeViewer` can hide every tool except the 3D Viewport.** The new `ui` prop takes a partial `MeganeViewerUiOptions` — `pipelineEditor`, `resetView`, `perfHud`, `timeline`, `tooltip`, `measurement` — where omitted keys stay visible, so you only list what you want gone: `<MeganeViewer ui={{ pipelineEditor: false }} />`. The type and the frozen all-visible defaults (`DEFAULT_MEGANE_VIEWER_UI`) are exported from `megane-viewer/lib`. Hiding a tool removes it from the DOM but not from the scene: the pipeline still executes, and the layout closes the gap — the camera frustum stops reserving the pipeline panel's width, the perf HUD takes the vacated Reset View slot, and the measurement panels drop to the corner whenever no timeline strip is on screen. The bundled hosts (webapp, VSCode webview, JupyterLab DocWidget) pass no `ui` prop and are unchanged.
- **<kbd>Esc</kbd> clears the atom selection, and closes the Render dialog.** A selection could previously only be cleared from the measurement panel — which `ui` can now hide. The shortcut is scoped to the viewer holding keyboard focus, and the Render and Share dialogs claim the key first, so dismissing a dialog leaves the selection alone. The Render dialog had no Escape handling before.

### Fixed

- **The AI chat box no longer crashes in JupyterLab.** The labextension's webpack build swaps `src/ai/skillLoader.ts` for a stub (the real module uses Vite's `import.meta.glob`), and the stub had not kept up with the OpenAI-compatible tool-calling work — it was missing `buildOpenAITools`, which `src/ai/client.ts` imports eagerly and calls for every non-Anthropic provider, the default free demo included. Sending a chat message from the JupyterLab DocWidget therefore threw `buildOpenAITools is not a function`. The stub now mirrors the real module's full export surface, and a unit test compares the two so the next added export cannot drift again.

- **Parser correctness fixes from the purity sweep:**
  - **DCD / AMBER NetCDF / AMBER inpcrd+prmtop**: unit-cell *angles* are now read (both NAMD cosine and CHARMM degree DCD conventions), so triclinic and truncated-octahedron boxes stop rendering as rectangular; fixed-atom DCDs (`NAMNF != 0`) are rejected with a clear error instead of decoding garbage.
  - **PSF**: elements are resolved from the file's mass column (CL/FE/ZN now parse as Cl/Fe/Zn instead of C/F/N), with the atom-name guess only as a fallback.
  - **GROMACS `.top`**: `[ settles ]` and `[ constraints ]` become bonds, so rigid water (TIP3P/SPC) renders bonded.
  - **mmCIF**: `_struct_conn` covalent records (disulfides, ligand links, metal coordination) become file bonds excluded from distance inference, and `_struct_conf`/`_struct_sheet_range` drive helix/sheet cartoons instead of everything rendering as coil.
  - **LAMMPS data**: distance-guessed bonds are no longer layered onto file-declared topology — inference only connects atoms the file leaves unbonded (e.g. free ions).
  - **MOL2 / Odyssey**: aromatic bond types map to the canonical MDL aromatic order 4, consistent with `.mol`/`.sdf`.
  - **XSF / CUBE**: ghost/dummy atoms (negative atomic numbers) are kept as element 0 (unknown) with a warning instead of rendering as real elements; CUBE's negative-`NAtoms` `DSET_IDS` records are decoded (first data set kept) instead of corrupting the voxel data.
  - **CML**: `units` attributes (bohr/au, pm, nm) on coordinates and crystal cell lengths are honored.
  - The LAMMPS-dump type→element remap for variable-atom trajectories returns new frames instead of mutating the parser's output in place.

- **The `Deploy LLM Proxy Worker` workflow could not install its dependencies.** A Dependabot bump pulled `wrangler` past the point where it requires `@cloudflare/workers-types@^5`, while `workers/llm-proxy/package.json` still asked for `^4`, so `npm ci` failed with `ERESOLVE` and every deploy since 2026-07-25 stopped at the install step. The dev dependency is now on `^5.20260801.1`. Note: the deploy also needs the workflow's Node version bumped to 22 for wrangler v4 and the `PLAMO_API_KEY` repository secret set (see Changed above).

- **Toggling the Wrap / Unwrap node no longer resets the camera zoom or the trajectory playhead.** A snapshot that only re-maps positions (same atoms, elements, bonds and cell) now reloads the geometry without the closing camera re-fit, so the user's zoom/orbit survives the toggle; a genuinely new structure still fits as before. The playback store likewise recognises a same-shape provider swap (a wrap/replicate node re-running over the same trajectory) and keeps the current frame, loop range, and play state instead of yanking playback back to frame 0.
- **Lazily decoded trajectory frames now respect wrapper nodes.** Asynchronously decoded frames (the XTC worker path, and streamed frames) were delivered to the playback store straight from the underlying decoder, bypassing any wrap or replicate provider sitting on top — so wrap/unwrap (and replication) silently did not apply to frames that arrived after the seek. The store now re-fetches the announced frame through its provider chain, applying the mapping.

## [0.13.1] - 2026-08-12

### Fixed

- **Four real-world file layouts from Jmol's demo corpus (`jsmol/data`) failed to load and now parse on every host.** Tested all 67 non-image files of that corpus against megane's parsers and fixed everything fixable:
  - **`.magres`** — CASTEP itself and CCP-NC's `format.py` delimit blocks with XML-style `<atoms>` … `</atoms>` rather than the documented `[atoms]` form; all three corpus files (`CuO2CCHF2.magres`, `croconic_new.magres`) were rejected with "[atoms] block contains no atom lines". Both spellings are now accepted.
  - **`.c3xml`** — Chem3D's native export (root `<C3XML version="10.0">`, e.g. `benzene.c3xml`) stores atoms as `<atom symbol cartCoords>` and bonds as `<bond bondAtom1 bondAtom2 bondOrder>`; the parser only knew the CDXML-style `<n Position>` dialect. Both dialects are now read.
  - **JCAMP-DX compound (link) files** (`##BLOCKS=n` — `Crspectra.jdx`, `pimentoGCMS2.dx`, `aquation20.jdx`, Bruker `*_assigned` exports) were scanned as if they were one spectrum, mixing titles/factors/data across embedded blocks. Blocks are now split and parsed independently; the first full-spectrum (`##XYDATA=`) block is returned, falling back to the first peak table. Header values also drop their `$$` inline comments, so titles like `Propan-2-ol 13C{1H} $$ Begin of the data block` come back clean.
  - **JCAMP-DX NTUPLES** (`##DATA CLASS=NTUPLES`, Bruker XWIN-NMR/TopSpin 1D exports such as `sample78-1hnmr.jdx`) failed with "no ##XYDATA= found". The real (`R`) `##DATA TABLE=` page is now decoded — imaginary page skipped, abscissa rebuilt from the X variable's `##FIRST=`/`##LAST=` since Bruker writes the X column as a raw point counter. True nD data (`##NUM DIM=` ≥ 2, e.g. `t2d.jdx`) is rejected with a message that says so instead of a misleading one.
  - **mmCIF under `.cif`** — macromolecular CIFs served with the small-molecule extension (wwPDB's `1cbs.cif`) failed with "CIF file contains no atom sites"; the CIF parser now detects dotted `_atom_site.` tags and delegates to the mmCIF parser.

## [0.13.0] - 2026-08-12

### Added

- **The `megane-viewer` npm package now ships TypeScript declarations.** `npm run build:lib` emits `dist/types/` (`tsc -p tsconfig.build-types.json` + a post-processing pass that strips stylesheet side-effect imports and adds explicit `.js` extensions so `moduleResolution: node16/nodenext` consumers resolve them), and the `.` / `./lib` exports carry `types` conditions. Deep imports of `./dist/widget.js` / `./dist/lib.js` and `./package.json` are exported as well.

### Fixed

- **The npm library bundle crashed React 18 hosts with `Objects are not valid as a React child`.** `vite.lib.config.ts` externalized only the exact specifiers `react` / `react-dom` / `three`, so subpath imports — most importantly `react/jsx-runtime`, which the automatic JSX transform emits — were bundled into `dist/lib.js`, baking in React 19's element symbol (`react.transitional.element`) that React 18's reconciler does not recognize. The externals are now prefix regexes (`/^react($|\/)/` etc.), so `react/jsx-runtime`, `react/jsx-dev-runtime`, `react-dom/client`, and `three/examples/jsm/*` all resolve from the host application (~147 kB smaller bundle). The anywidget `widget.js` bundle intentionally stays fully self-contained. Verified by rendering `MeganeViewer` from the packed tarball on both React 18 (previously crashed, now renders) and React 19 hosts.

## [0.12.0] - 2026-08-10

### Changed

- **`megane-viewer` now supports React 18 and React 19.** `react` / `react-dom` moved from `dependencies` to `peerDependencies` (`^18.2.0 || ^19.0.0`) — the npm library bundle has always externalized React and used the host app's copy, but the old `dependencies` entry forced React 19 into consumers' trees and risked a duplicate React. Development and the self-contained bundles (webapp, anywidget, VSCode webview) stay on React 19; the JupyterLab labextension already ran on the host's React 18. ## [0.11.0] - 2026-08-02

### Added

- **Selection Inspector** — a third pipeline-panel tab for OVITO-style "select a subset, change how it looks" without hand-writing expressions. Selections are built from structure-aware element/residue/chain chips, a distance radius, the raw expression (two-way), or 3D box-drag / click "quick expand" picking, and are highlighted live in the viewer. Each layer compiles to ordinary filter → color/representation/modify pipeline nodes via a pure, idempotent reconcile step, so edits made in the Inspector appear verbatim in the Editor tab — the pipeline store stays the single source of truth. The selection DSL gains `chain`, `resid`, and a `within R of (...)` operator, kept in sync with the LLM prompt, node catalog, and Filter node hint.
- **LAMMPS dump files open standalone** (`.lammpstrj`, `.dump`, and the newly registered `.trj`) as multi-frame structures on every host, instead of requiring a separate topology to be loaded first. Frame 0 defines the topology and the remaining frames stream into playback, like a multi-frame XYZ or ASE `.traj`. A dump carries no element symbols or masses, so the integer per-atom `type` id is used as the atomic-number proxy and bonds are inferred by distance from frame 0. The existing "attach onto a loaded topology" path is preserved. Python gains `load_lammpstrj_structure`.
- **Molden files** (`.molden`) on every host. The `[Atoms]` block becomes the structure, honouring its `(AU)` / `(Angs)` unit argument, and a `[GEOMETRIES] XYZ` block loads as a multi-frame optimisation via the shared XYZ frame reader. `[GTO]`/`[MO]` orbitals, `[FREQ]` normal modes, and any vendor-specific section are skipped tolerantly.
- **XCrySDen structure files** (`.xsf` / `.axsf`) on every host. Handles the `CRYSTAL` / `SLAB` / `POLYMER` / `MOLECULE` / `ATOMS` dimensionality keywords, `PRIMVEC` lattice vectors, and `PRIMCOORD` atom blocks; an `ANIMSTEPS` `.axsf` loads as a multi-frame structure with per-frame cells for variable-cell animations. The optional per-atom force triple is exposed as a `force` vector channel for the Vector Overlay node. `CONVVEC` is consumed and discarded, and `BEGIN_BLOCK_DATAGRID_*` volumetric blocks are skipped.
- **JCAMP-DX spectra** (`.jdx`, `.jcamp`, `.dx`) on every host, via two new pipeline nodes: **Load Spectrum** and the terminal **Spectrum Plot**, which draws the trace as a 2D line chart (abscissa reversed by default, the IR/NMR convention). Decoding covers plain AFFN plus all three compressed ASDF forms — SQZ, DIF, and DUP — for both `##XYDATA=(X++(Y..Y))` and `##XYPOINTS=(XY..XY)` tables. Because `.dx` is claimed by both JCAMP-DX and OpenDX volumetric grids, the two are told apart by sniffing the file head, and a misrouted file gets an actionable message pointing at the other node. Python gets `megane.load_jcampdx()` returning a `Spectrum` (title, units, x, y) and the `LoadSpectrum` / `SpectrumPlot` pipeline classes.
- **Jmol's `.jxyz` extension** is now accepted on every host. It is plain XYZ under a second name, so it aliases to the existing XYZ reader rather than adding a parser — megane's XYZ already handles multi-frame blocks, `Lattice=` extended headers, and the extra per-atom columns Jmol writes after x/y/z.
- **Chem3D XML** (`.c3xml`) on every host, reusing the `quick-xml` reader added for CML. `<n>` nodes and `<b>` bonds give explicit connectivity and bond orders; 2D-only drawings are projected onto z = 0 without inventing bonds.
- **Wavefunction Odyssey files** (`.xodydata`, `.odydata`) on every host, reusing the `quick-xml` reader added for CML. Odyssey ships two unrelated layouts, and one parser reads both by sniffing the **content rather than the extension**: the XML `<odyssey_simulation>` document (`<atom element= xyz=>`, `<bond a= b= order=>`, `<boundary box=>`) and the older Spartan-style text layout (`ENDCART` / `ATOMLABELS` / `HESSIAN` … `ENDHESS`). Bond orders may be `s`/`d`/`t`/`a` or integers, with aromatic collapsing to 1 for display as in `.mol2`; a periodic `<boundary>` shifts the box-centred coordinates into a cell drawn at the world origin. Wavefunction publishes no schema, so the reader is written against the vocabulary its files use and errors out rather than guessing. Formal charges (`<group charge>`) are skipped — there is no formal-charge channel — and wavefunction-based surfaces are not stored in these files at all.
- **Chemical Markup Language** (`.cml`) on every host — the first XML format in `megane-core`. Reads the first `<molecule>` with atoms, honouring `x3`/`y3`/`z3`, packed `xyz3`, `xFract`/`yFract`/`zFract` (with the `<crystal>` cell), and 2D `x2`/`y2` depictions projected onto z = 0. An explicit `<bondArray>` supplies connectivity and bond orders; without one, bonds are inferred by distance.
- **CASTEP NMR magres files** (`.magres`) on every host. The `[atoms]` block becomes a periodic structure, with each block's own `units` declaration honoured (Angstrom or bohr, lattice and atoms independently). The `ms`/`efg`/`isc` tensors and the old-style pre-2010 grammar are out of scope; the latter is rejected with a clear message.
- **GAMESS output** (`.gamess`) on every host. Every `COORDINATES OF ALL ATOMS ARE` block becomes a frame, so a geometry optimisation scrubs on the timeline; the `(ANGS)`/`(BOHR)` banner is honoured and ECP fractional charges fall back to the atom label. Only `.gamess` is registered — claiming `.log`/`.out` would hijack every log file in a workspace.
- **CASTEP phonon files** (`.phonon`) on every host, structure half. The header's unit cell, fractional coordinates, and species render as a periodic structure. Frequencies and complex eigenvectors are parsed into a `PhononModes` struct ready for a follow-up mode-animation node, which should be shared with Molden `[FREQ]` rather than duplicated.
- **VASP structure files** (`POSCAR`, `CONTCAR`, `XDATCAR`, `.vasp`) on every host. `XDATCAR` opens as a multi-frame structure, including variable-cell (ISIF ≥ 3) runs that re-emit the header per configuration. Because the standard VASP filenames carry no extension, megane now also dispatches by **basename** (`src/parsers/fileNames.ts`); VS Code registers `POSCAR*` / `CONTCAR*` / `XDATCAR*` globs and JupyterLab an `IFileType.pattern`. VASP 4 files with no species line fall back to the 1-based species index as an atomic-number proxy instead of failing.
- **OpenDX volumetric grids** (`.dx`) in the Load Volumetric node, alongside the existing Gaussian CUBE reader — the de-facto APBS electrostatics output. The node's accept list is now multi-format and dispatches by extension.
- **Volumetric grids are registered on JupyterLab and VS Code.** Opening a `.cube` / `.cub` / `.dx` standalone now surfaces an actionable "load a structure first, then add a Load Volumetric node" message instead of feeding the grid to the structure parser.
- The volumetric formats now have their own table in `docs/docs/platform-support.md` — `.cube` had never been documented.

### Changed

- `megane-core` now depends on **`quick-xml`** (pull parser, no DTD processing or custom entity expansion, so untrusted XML cannot mount an XXE / billion-laughs attack). Cost to the browser bundle: `megane_wasm_bg.wasm` grows from 544,125 to 586,372 bytes raw (203,106 → 217,087 gzipped, **+6.9 %**), measured on an unoptimized `wasm-opt`-free build.

### Fixed

- **GIF export in the VS Code extension** produced no file: the progress bar advanced and then nothing happened, while PNG and MP4 saved normally. GIF is the only export that spawns a Web Worker (gif.js encodes there), and the webview bundle is built with Vite's default `base: "/"`, so the emitted worker URL was `/gif.worker.js` — the origin root, not the `media/` directory the file actually ships in. gif.js never listens for its worker's `onerror`, so the encode produced no Blob and the extension-host save bridge was never reached. The worker source is now inlined into every host bundle and wrapped in a `blob:` URL at runtime, so it no longer depends on a host's asset base path — the same failure that hit JupyterLab as #497 and VS Code as #599.
- `serializePipeline` now strips the ephemeral `volumetricData` from Load Volumetric params, which its own type had always documented as "not serialized".
- **Structures offset from the world origin rendered off-screen.** LAMMPS data/dump files can define a simulation box whose lower corner is far from the origin (e.g. `600 900 zlo zhi`) with absolute atom coordinates inside it. megane discarded the box origin and kept only the edge lengths, so the cell wireframe was always anchored at (0,0,0) while the atoms stayed at their absolute positions — the camera framed the empty cell and the atoms were nowhere in view. The box origin is now carried through the whole pipeline (`megane-core` → WASM/PyO3 → TypeScript → renderer, including the Python→JS widget protocol) and the cell is drawn at its true location with atom coordinates left absolute, matching OVITO. Formats that specify no origin default to (0,0,0), reproducing the previous output byte-for-byte.
- **Two CodeQL high-severity alerts in the selection helpers.** `parseResid` used a lookahead-over-`.*` regex with polynomial worst-case matching time against atom labels read from untrusted files (ReDoS); it is now a linear back-to-front scan with the same "last run of digits" semantics. `quoteValue` escaped `"` but not the escape character itself (incomplete string sanitization); since the selection DSL has no unescape step, both `"` and `\` are now stripped from values rather than emitted as undecodable escapes.
- The Python pipeline builder no longer raises when a node id is absent — the optional id is narrowed before the dict lookup.
